# Development keys and secrets

Phase 1 ships everything needed to run locally, including signing keys, without any secret
that could be mistaken for a production one.

| Item | Development value | Production behaviour |
|---|---|---|
| Session signing key `OC_SECRET_KEY` | committed constant in `settings.py` | api refuses to start with it, or with any key under 32 characters |
| api ↔ signer secret `OC_SIGNER_SHARED_SECRET` | committed constant | api and signer refuse to start with it |
| Signer KEK `SIGNER_KEK` | committed constant (`dev:committed` in `keys.private_keys.kek_ref`) | signer refuses to start with it |
| Demo issuer key | generated by the signer on `oc seed`, stored encrypted, `issuer_keys.is_dev = true` | api refuses to start while any dev key is `active`; signer refuses to start while any dev key exists; signer refuses to create dev keys |
| Demo issuer | `did:key`, name ends "(DEVELOPMENT)" | production issuers use `did:web` on the institution's verification host (ADR-0004) |
| Development login `/dev/*` | mounted outside production, only for institutions flagged `is_demo` | not mounted; no setting re-enables it |

No private key is committed to the repository. Each `oc seed` generates a fresh key, so dev
credentials from one machine never verify as coming from another.
